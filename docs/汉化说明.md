### "业务逻辑零改动"的准确含义

**不是"只有文本变了"。** 三个文件带翻译层代码：

- `overlay-panel.js`、`overlay-gallery.js`：游戏内叠加层是独立的离屏文档（`overlay-panel.html`），**不经过**主界面的 `data-i18n` 机制。只能用「遍历文本节点 + 替换 + `MutationObserver` 监听后续 DOM 变更」的方式翻译。
- `overlay-bridge.js`：主窗口与叠加层之间的语言同步通道。

这套做法沿用自 2.2.9 的汉化（该文件在 2.2.9 安装包里本来就带 `OL_ZH` 映射表）。**它不改变任何安装、注入、还原、扫描逻辑**，只影响界面上显示什么字。

其余 7 个文件：字典数据（2 个）+ HTML 挂载点（1 个）+ 纯字符串替换（4 个）。

## 四、翻译过程中处理的几类"翻不到"的地方

按发现顺序：

1. **字典键缺中文** —— 最直接的一类，补 `S.zh`。
2. **HTML 有 `data-i18n` 但 JS 不刷新的静态文案** —— 如 `olCustom`（`index.html:235`），没有任何 JS 写入，只能进 `OL_ZH` 兜底。
3. **不经 `data-i18n`、由 JS 每次 `open()` 刷写的文案** —— 如 `olEnabledLabel` / `olHotkey` / `olAdd` / `olSource`（`overlay-gallery.js:25-26` 的 `text()` 走 `GALLERY_ZH`）、`olPreviewLabel` / `olCustomTitle`（`:19`、`:83`）。必须同时补 `GALLERY_ZH` 与 `OL_ZH`。
4. **模板字符串拼出来的句子** —— 如首页的 `Found ${n} games across ${m} sources`（`renderer.js:671` 硬编码）。改为 `t('scanSummary', n, m)` 函数型词条，并在 `i18n.js` 的 en/zh 各加一条。
5. **主进程返回英文、优先级高于字典兜底** —— 社区页离线提示 `community.js`：`response?.message || text().offline`。主进程 `communityAnswer`（`main.js:60/62`）返回的 `message` 永远是英文，字典兜底永远轮不到。修法：按错误码选译文，只有非已知错误码才回落到服务端原文。
6. **切语言时不重绘的局部状态** —— 社区页计数 `communityGameTotal`，`applyLanguage()` 重置了所有筛选标签但没重算计数。修法：state 里记住 `total`，切语言时按当前 scope 重算。

第 5、6 两条严格说不是"翻译"，不改就是中文界面里夹一句英文，属于必须一起解决的问题。

### 审计方法

英文残留审计**必须按可见性收敛**，否则数字永远降不到 0。第一版脚本走全量文本节点，把隐藏对话框、`hidden` 元素、未展开的菜单都算了进去。改成只统计满足以下全部条件的节点后才有意义：

- 自身与**全部祖先**的 `getComputedStyle` 都不是 `display:none` / `visibility:hidden` / `opacity:0`
- `n.hidden` 为假
- `getBoundingClientRect()` 宽高都 > 1

### 什么不算"英文残留"

游戏名（`IXION`、`STEINS;GATE`、`FINAL FANTASY VII REMAKE INTERGRADE`、`HITMAN™ 2`…）、文件路径（`E:\SteamLibrary\steamapps\common\...`）、渲染 API 徽标（`DirectX 12`、`Vulkan`、`OpenGL`）、状态徽标（`BETA`、`LIVE`、`ZH`）、品牌行（`by SmarterGamers`）、DLL 文件名（`renodx-dlss5.addon64`）。

这些按 Q4=A 的决定保持原样——把 `DirectX 12` 翻成「直接X十二」对用户没有价值。

## 六、顺带修掉的两个上游缺陷

不是汉化引入的问题，是 2.3.0 本身就有，看到就一起修了：

### 1. 插件页显示 `null替换内置插件`

- 根因：`main.js:141` `label: known.name || label`。payload 来源的调用是 `add(p.source.addon, null)`（`main.js:176`），`label` 为 `null`；而 `renderer.js:4` 的 `esc = (s) => String(s).replace(...)`，`String(null)` 得到**字符串 `"null"`**。
- 另一层：addon 内容 sha1 前 16 位 `400f6141d6c2c672` 不在 `KNOWN` 表里（表里只有 `189efdee6a327833`、`0c0a02578d2aadf2`、`88116071ef689864`），所以查不到名字。
- 修法：`esc(a.label || a.file)`。已用未修改的上游 `main.js` 第 141 行复核，确认是上游原生缺陷，不是汉化改坏的。

### 2. 社区页切语言后计数不刷新

- 根因：`community.js` 的 `applyLanguage()`（约 314 行）重置了全部筛选标签，但没有重新渲染 `communityGameTotal`。
- 修法：state 增加 `total` 字段；`render()` 在写文案前记下服务端返回的 total；`applyLanguage()` 末尾按当前 scope 重算（`all` 用 total、`mine` 用卡片数、`reports` 用报告数）。

这两个修复在 `app.asar` 层面同样生效，不是只存在于源码树。

## 七、重打包说明（给想自己重新打包的人）

`resources/app.asar` 是 Electron ASAR 格式，结构：

```
[0..16)      Pickle 头：u32=4, u32=headerSize+4, u32=headerSize, u32=jsonLen
[16..16+jsonLen)   JSON 目录（尾部 NUL 补齐到 4 字节对齐）
[dataStart..]      各条目数据，dataStart = 16 + ceil(jsonLen/4)*4
```

**关键点**：`u12`（`jsonLen`）是**真实 JSON 长度，不含 padding**；`dataStart` 必须按 `ceil(jsonLen/4)*4` 对齐。按 `16 + jsonLen` 算会整体错位，表现为所有"未改动文件"都比对失败（我第一次就踩了这个坑，报 184 个假失败）。

重打包必须原样保留全部 182 个条目，其中包括 `node_modules` 45 个文件（`extract-zip` 及其依赖，被 `.gitignore` 忽略、不在源码树里）和大体积二进制：

| 文件 | 大小 |
|---|---:|
| `resources/payload/streamline/nvngx_dlssnr.dll` | 158.2 MB |
| `resources/payload/streamline/nvngx_dlss.dll` | 56.2 MB |
| `resources/payload/streamline/nvngx_dlssd.dll` | 46.1 MB |
| `resources/payload/streamline/nvngx_dlssg.dll` | 7.1 MB |
| `resources/payload/reshade-vulkan/ReShade64.dll` | 5.3 MB |

`app.asar` 内 `package.json` 与源码树的 `package.json` **不同**：前者被 electron-builder 精简掉 `scripts` / `devDependencies` / `build` 段，且末尾无换行。重打包时不能拿源码树的 `package.json` 顶替。

## 八、升级风险

上游**没有内置自动更新器**：全部 JS 里搜不到 `autoUpdater`、`electron-updater`、`checkForUpdates`。`resources/app-update.yml` 只是 electron-builder 的产物（`owner: SmarterGamers`、`repo: SmarterGamers-DLSS5-Swapper`、`provider: github`），没有代码去读它。

**但是**：手动下载新版重装会**整包覆盖** `resources\app.asar`，汉化随之消失。

重装之后：

| 情况 | 做法 |
|---|---|
| 版本仍是 2.3.0 | 直接再跑 `install-zh-CN.ps1` |
| 版本变了 | **不能复用本补丁**。字典结构、硬编码文案、叠加层 DOM 都可能变了，需按第九节重新做 |

`install-zh-CN.ps1` 会读取目标 asar 内 `package.json` 的 `version` 字段做守卫，不是 2.3.0 时要求二次确认；读不出时警告后要求确认。

## 九、上游发新版后怎么重新汉化

1. 下载新版源码树（`git clone --depth 1 --branch vX.Y.Z`）
2. 用本仓库这 10 个文件覆盖对应路径
3. 检查 `i18n.js`：新版 `en` 块有哪些键是旧的没有的 → 补译；有哪些键被删了但 HTML 还在用 → 补回孤儿键
4. 检查 `feature-i18n.js`：同上
5. 检查各渲染器里的硬编码英文：`grep` 中文全角标点周围、`textContent =`、`innerHTML =` 后的英文字面量
6. 启动应用，用可见性审计脚本逐视图扫一遍
7. 重新打包 asar，跑结构校验
8. 更新本文档里的字节数与哈希

第 3～5 步是最容易漏的：字典 100% 不等于界面 100%，硬编码文案和 JS 每次刷写的文案都不走字典。
