# 验收清单 · 怎么自己核对这份汉化

本文列出**可复现**的核对命令与预期输出。每一条都在这台机器上真实跑过，不是"应该会通过"。

如果你发现哪条对不上，说明文件被改过或版本不匹配。

## 二、改动面：恰好 10 个文件

把本仓库与上游 tag 各自的文件表导出，比 blob 哈希：

```bash
# 上游
git -C /path/to/upstream ls-tree -r v2.3.0 > /tmp/up.tree

# 本仓库
git -C /path/to/this-repo ls-tree -r HEAD > /tmp/my.tree

awk '{print $3" "$4}' /tmp/up.tree | sort -k2 > /tmp/a.txt
awk '{print $3" "$4}' /tmp/my.tree | sort -k2 > /tmp/b.txt

diff /tmp/a.txt /tmp/b.txt | grep '^[<>]' | awk '{print $3}' | sort -u
```

预期输出**恰好 10 行**：

## 三、字典覆盖

不能用正则数行——英文串里可能含冒号，函数型词条跨多行。正确做法是真的把文件当代码执行：

```javascript
const fs = require('fs');
const vm = require('vm');

const ctx = { window: {}, console };
vm.createContext(ctx);
vm.runInContext(fs.readFileSync('src/renderer/i18n.js', 'utf8'), ctx);

const S = ctx.window.i18n.S;
for (const [lang, table] of Object.entries(S)) {
  console.log(lang, Object.keys(table).length);
}
```

预期：

```
en 278
zh 278
ar 267
es 81
pt 81
ru 81
de 81
fr 81
ja 81
ko 81
it 81
tr 81
pl 81
```

差集检查（没有键缺中文）：

```javascript
const en = new Set(Object.keys(S.en));
const zh = new Set(Object.keys(S.zh));
console.log('missing in zh:', [...en].filter(k => !zh.has(k)));
console.log('extra in zh:', [...zh].filter(k => !en.has(k)));
```

预期：两个数组都是空的。

副字典同理，注意它是 `module.exports` 与 `root.featureI18n` 二选一导出：

```javascript
const mod = { exports: {} };
const ctx = { module: mod, exports: mod.exports, require, console, window: {} };
ctx.window = ctx;
vm.createContext(ctx);
vm.runInContext(fs.readFileSync('src/shared/feature-i18n.js', 'utf8'), ctx);
const cat = (ctx.featureI18n || mod.exports).catalog;
console.log('en', Object.keys(cat.en).length, 'zh', Object.keys(cat.zh).length);
```

预期：`en 86 zh 86`

## 五、仓库源码 = 发货 asar 内的文件

这条最重要：仓库里放的必须就是成品里跑的那份。

```javascript
const fs = require('fs');
const buf = fs.readFileSync('app.asar');
const jsonLen = buf.readUInt32LE(12);
const hdr = JSON.parse(buf.slice(16, 16 + jsonLen).toString('utf8').replace(/\0+$/, ''));
const base = 16 + Math.ceil(jsonLen / 4) * 4;   // 注意：不是 16 + jsonLen

function entry(p) {
  let n = hdr;
  for (const part of p.split('/')) n = n.files[part];
  return n;
}

for (const f of [
  'main.js', 'src/overlay-bridge.js', 'src/renderer/chat.js',
  'src/renderer/community.js', 'src/renderer/i18n.js',
  'src/renderer/index.html', 'src/renderer/overlay-gallery.js',
  'src/renderer/overlay-panel.js', 'src/renderer/renderer.js',
  'src/shared/feature-i18n.js',
]) {
  const e = entry(f);
  const fromAsar = buf.slice(base + Number(e.offset), base + Number(e.offset) + Number(e.size));
  // 仓库工作区是 CRLF，asar 里是 LF，比较前归一化
  const fromRepo = Buffer.from(
    fs.readFileSync(f, 'utf8').replace(/\r\n/g, '\n'), 'utf8'
  );
  console.log(Buffer.compare(fromAsar, fromRepo) === 0 ? 'MATCH' : 'DIFF ', f);
}
```

预期：10 行全部 `MATCH`。

## 六、asar 结构校验

重打包后必须验这些，否则应用起不来：

| 项 | 预期 |
|---|---|
| 头 16 字节 `u32` | `4`、`headerSize+4`、`headerSize`、`jsonLen` |
| `u4 == u8 + 4` | true |
| `u12` | 真实 JSON 长度，**不含** padding |
| padding | `ceil(jsonLen/4)*4 - jsonLen`（2.3.0 实测为 3） |
| `dataStart` | `16 + ceil(jsonLen/4)*4` |
| 条目总数 | 182 |
| 二进制条目 | 与解包前的原包逐字节相同 |

**最容易踩的坑**：用 `16 + jsonLen` 算数据起点。因为 JSON 尾部有 NUL padding，这样算会整体偏移 1～3 字节，表现为所有"未改动文件"都校验失败。

我在过程中就踩过这个坑，一次报出 184 个假失败（全部 untouched 文件"differ"），修正为 `align4` 后全部通过。

## 七、运行时验证

### 语言确实生效

启动应用后，通过 DevTools 控制台或 CDP：

```javascript
window.i18n.getLang()            // 'zh'
document.documentElement.lang    // 'zh'
// 缺键自检：遍历 en 全部键，看 zh 是否都能取到非英文文案
```

### 语言往返切换

**不要直接调 `window.i18n.setLang()`**。它只改字典，不触发 `applyLang()` 重绘，`chat.js` / `community.js` 自建映射表不会更新，会看到"中文导航夹英文内容"的假象。

必须走真实 UI 路径：点 `#langBtn` 打开菜单 → 点 `[data-lang="en"]` → 再切回 `zh`。

### 语言持久化

```bash
cat "$LOCALAPPDATA/../Roaming/SmarterGamers DLSS 5 Swapper/library.json" | grep lang
```

切到英文后应为 `"lang": "en"`，切回中文后应为 `"lang": "zh"`；重启应用后仍保持。

### 英文残留审计

**必须按可见性过滤**，否则数字永远降不到 0（隐藏对话框、未展开菜单、`hidden` 元素都会被算进去）：

```javascript
const visible = (n) => {
  if (n.hidden) return false;
  let el = n.parentElement;
  while (el) {
    const s = getComputedStyle(el);
    if (s.display === 'none' || s.visibility === 'hidden' || s.opacity === '0') return false;
    el = el.parentElement;
  }
  const r = n.getBoundingClientRect();
  return r.width > 1 && r.height > 1;
};
```

过滤后剩下的应当是游戏名、文件路径、渲染 API 徽标、`BETA`/`LIVE`/`ZH` 状态徽标、品牌行、DLL 文件名。

## 八、补丁脚本

```powershell
$t = $null; $e = $null
[System.Management.Automation.Language.Parser]::ParseFile(
  'patches\install-zh-CN.ps1', [ref]$t, [ref]$e
) | Out-Null
if ($e.Count -gt 0) { $e | ForEach-Object { $_.Message } } else { 'PARSE OK' }
```

预期：`PARSE OK`

**坑**：`$t` 和 `$e` 必须先单独赋 `$null` 再传 `[ref]`。直接内联写会报"无法将 [ref] 应用于不存在的变量"。

另：脚本必须存为 **UTF-8 with BOM**。PowerShell 5.1 在没有 BOM 时按 ANSI（简中系统即 GBK）解码，中文注释会破坏语法，报 `MissingEndCurlyBrace` 或"表达式或语句中包含意外的标记"。

检查 BOM：

```powershell
[System.IO.File]::ReadAllBytes('patches\install-zh-CN.ps1')[0..2] -join ','
```

预期：`239,187,191`（即 `EF BB BF`）。

## 九、哈希对照

| 文件 | SHA-256 | 大小 |
|---|---|---:|
| 官方原包 `app.asar` | `7250e1058a90569a96742bc07396f4fa616d61702bf2479fa473992f9307df43` | 313,955,671 |
| 汉化后 `app.asar` | `5ccf3b6e05c4a40369598fab3e9b6f16ba2aca1096b2d2937c9a0aa82fe086a4` | 314,003,461 |

校验：

```bash
sha256sum app.asar
```

Release 里的 `app.asar` 应与第二行完全一致。如果你的官方原包算出来不是第一行，说明你的版本不是 v2.3.0，本补丁不适用。
